2준비운동 — 이 코드에 계속 나오는 문법 10개

이 10개만 알면 코드의 90%가 읽힙니다. 전부 실제 우리 코드에서 뽑았습니다.

① 데코레이터 @ — “이 함수를 감싸서 뭔가 더 해라”

@bp.get("/me")          # ← 이 함수를 GET /me 주소에 연결해라
@login_required          # ← 이 함수 실행 전에 로그인 검사부터 해라
def me():
    ...

@가 붙으면 함수를 다른 함수에 “집어넣는다”는 뜻입니다. me라는 함수를 만든 다음, login_required(me)를 실행해서 나온 새 함수를 다시 bp.get("/me")(...)에 넘깁니다. 가까운 데코레이터(@login_required)가 먼저 적용되고, 위에 있는 게 나중에 감쌉니다.

문법

데코레이터는 “함수에 붙이는 스티커”라고 생각하면 됩니다. 스티커가 원래 함수를 감싼 새 함수를 만들어 냅니다. 그래서 auth.py의 login_required 안에 def wrapper(...)가 들어 있는 겁니다 — 그 wrapper가 진짜로 등록되는 함수예요.

② with — “쓰고 나서 반드시 뒷정리해라”

with db.get_cursor(commit=True) as cur:
    cur.execute("UPDATE ...")
# ← 이 줄로 나오는 순간 커밋 + 커넥션 반납이 자동으로 일어난다

블록을 벗어날 때(정상 종료든, 예외로 튕겨 나가든) 정리 코드가 반드시 실행됩니다. DB 커넥션을 반납 안 하고 새면 서버가 몇 분 만에 멎기 때문에 이걸 씁니다.

③ := 왈러스 연산자 — “대입하면서 동시에 검사”

if status := request.args.get("cctv_status"):
    where = "WHERE cctv_status = %s"

status = request.args.get(...)를 하고 그 값이 참이면 if 안으로 들어갑니다. 두 줄을 한 줄로 줄인 것뿐입니다.

④ f-string f"..." — 문자열 안에 값 끼워넣기

raise ApiError(400, "BAD_REQUEST", f"{field} 는 필수입니다.", field=field)
# field 가 "user_pw" 면 → "user_pw 는 필수입니다."

⑤ 타입 힌트 -> dict | None — “돌려주는 값의 종류”

def query_one(sql: str, params: tuple = ()) -> dict | None:

“sql은 문자열, params는 튜플(기본값은 빈 튜플), 돌려주는 건 dict 또는 None”이라는 메모입니다. 파이썬은 이걸 강제하지 않습니다 — 어겨도 에러가 안 납니다. 읽는 사람과 에디터를 위한 표시일 뿐입니다.

⑥ dict = 딕셔너리 — 이 프로젝트의 기본 데이터 모양

row = {"event_no": 12, "event_status": "CONFIRMED"}
row["event_no"]        # 12  — 키가 없으면 에러
row.get("없는키")        # None — 키가 없어도 에러 안 남

이 프로젝트는 ORM(모델 클래스)을 안 씁니다. DB에서 읽은 행이 그대로 dict로 오고, 그 dict를 그대로 JSON으로 내보냅니다. 그래서 코드 어디를 봐도 row["cctv_name"] 같은 게 계속 나옵니다.

⑦ %s 파라미터 바인딩 — SQL 인젝션 방어

db.query_one("SELECT ... FROM users WHERE user_id = %s", (user_id,))
#                                              ↑ 여기에 값을 "따로" 넘긴다
함정

%s는 파이썬 문자열 포맷이 아닙니다. psycopg2(=DB 드라이버)에게 “여기에 값이 들어갈 자리”라고 알려주는 표시이고, 값은 SQL과 분리해서 전달됩니다. 그래서 user_id에 ' OR 1=1-- 같은 걸 넣어도 그냥 그런 이름의 아이디를 찾을 뿐 공격이 안 됩니다.
절대 f"WHERE user_id = '{user_id}'"처럼 쓰면 안 됩니다.

우리 코드에도 f-string으로 만든 SQL이 있는데(f"SELECT ... {where}"), 거기 끼워 넣는 건 우리가 직접 쓴 문자열("WHERE cctv_status = %s")이고 사용자 값은 여전히 %s로 나갑니다. 이건 안전합니다.

튜플에 값이 하나면 (user_id,)처럼 쉼표를 반드시 찍어야 합니다. (user_id)는 그냥 괄호일 뿐 튜플이 아닙니다.

⑧ 예외 raise / try-except

raise ApiError(404, "USER_NOT_FOUND", "사용자를 찾을 수 없습니다.")

raise는 “여기서 던지고 함수를 즉시 중단”입니다. 우리 코드에서는 이걸 던지면 errors.py에 등록해 둔 처리기가 받아서 {"code":"USER_NOT_FOUND","message":"..."} + HTTP 404로 자동 변환해 줍니다. 라우트마다 에러 응답을 만들 필요가 없는 이유입니다.

⑨ 모듈 = 파일 하나, import = 다른 파일 가져오기

import db                       # db.py 전체 → db.query(...) 로 사용
from errors import ApiError     # errors.py 안의 ApiError 만 → ApiError(...) 로 사용
from services import hooks      # services 폴더의 hooks.py → hooks.on_event_confirmed(...)

5.1 app.py — 서버를 조립하고 켠다 (81줄)

파일이 하는 일은 4가지입니다: ① JSON 변환 규칙 정의 ② 스케줄러 시동 ③ 앱 조립 ④ 실행.

back/app.py — ① JSON 변환 규칙
class ApiJSONProvider(DefaultJSONProvider):
    """명세서 공통 규칙: 날짜는 ISO 8601, numeric 은 숫자로 내보낸다."""
    @staticmethod
    def default(obj):
        if isinstance(obj, (datetime, date)):
            return obj.isoformat()
        if isinstance(obj, Decimal):
            return float(obj)
        return DefaultJSONProvider.default(obj)
왜 이렇게 했나

DB에서 읽은 값은 파이썬 datetime과 Decimal 객체입니다. 기본 JSON 변환기는 이걸 어떻게 문자로 바꿀지 몰라서 "Object of type datetime is not JSON serializable" 에러를 냅니다. 그렇다고 라우트마다 str(row["created_at"])을 쓰면 ① 빼먹기 쉽고 ② 날짜 형식이 파일마다 달라집니다.
여기서 한 번 규칙을 정하면 모든 응답이 자동으로 "2026-08-11T09:00:00"(ISO 8601)과 숫자 37.5665로 통일됩니다. Decimal → float가 중요한 이유: 안 하면 위경도가 JSON에서 "37.5665000" 문자열로 나가서 프론트가 지도에 못 찍습니다.

트랜잭션 — 이 파일에서 제일 중요한 함수

@contextmanager
def get_cursor(commit: bool = False):
    pool = _get_pool()
    conn = pool.getconn()                  # ① 연결을 빌린다
    try:
        with conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor) as cur:
            yield cur                  # ② 여기서 with 블록 본문이 실행된다
        if commit:
            conn.commit()                  # ③ 확정
        else:
            conn.rollback()                #    조회는 되돌린다
    except Exception:
        conn.rollback()                    # ④ 터지면 전부 취소
        raise
    finally:
        pool.putconn(conn)                 # ⑤ 무슨 일이 있어도 반납
문법

@contextmanager + yield는 “with로 쓸 수 있는 함수”를 만드는 방법입니다. yield 앞부분 = 블록에 들어가기 전 실행, yield로 넘긴 값 = as cur의 cur, yield 뒷부분 = 블록을 나올 때 실행.

try / except / finally: finally는 무조건 실행됩니다. 성공해도, 예외가 나도, 중간에 return 해도. 그래서 커넥션 반납을 여기 둡니다. raise를 단독으로 쓰면 “방금 잡은 예외를 그대로 다시 던져라”입니다 — 롤백만 하고 에러는 위로 전달합니다.

왜 이렇게 했나

RealDictCursor. 기본 커서는 결과를 (1, '정문 카메라', 37.5665) 같은 튜플로 줍니다. 그러면 row[1]처럼 번호로 꺼내야 해서, SELECT 컬럼 순서를 바꾸는 순간 전부 깨집니다. 이 커서는 {"cctv_no":1, "cctv_name":"정문 카메라"} dict로 줘서 row["cctv_name"]으로 쓸 수 있습니다.

조회에서도 rollback 하는 이유. SELECT만 해도 PostgreSQL은 트랜잭션을 엽니다. 안 닫고 연결을 반납하면 그 연결이 “idle in transaction” 상태로 남아 다른 트랜잭션을 막습니다. rollback은 “아무것도 안 했으니 닫아라”라는 뜻입니다.

execute 여러 번 vs get_cursor 한 번 — 차이가 중요합니다

# (A) 각각 별개 트랜잭션 — 사이에 다른 요청이 끼어들 수 있다

def _decode_token() -> dict:
    header = request.headers.get("Authorization", "")
    if not header.startswith("Bearer "):
        raise ApiError(401, "UNAUTHORIZED", "인증 토큰이 필요합니다.")
    token = header.removeprefix("Bearer ")
    try:
        return jwt.decode(token, config.JWT_SECRET, algorithms=["HS256"])
    except jwt.ExpiredSignatureError:
        raise ApiError(401, "TOKEN_EXPIRED", "토큰이 만료되었습니다. 다시 로그인해주세요.")
    except jwt.InvalidTokenError:
        raise ApiError(401, "INVALID_TOKEN", "유효하지 않은 토큰입니다.")

@wraps(f) = “원래 함수의 이름표를 wrapper에 복사”. 이게 없으면 플라스크가 보기에 모든 라우트 함수 이름이 wrapper가 돼서 두 번째 라우트를 등록할 때 “이름이 겹친다”고 에러가 납니다. 데코레이터를 만들 때 사실상 필수입니다.

왜 이렇게 했나

AI 모델은 왜 JWT를 안 쓰나. AI 모델은 사람이 아니라 프로그램이라서 “로그인 → 토큰 받기 → 만료되면 재로그인”을 할 이유가 없습니다. 그냥 .env에 미리 공유한 키 하나(X-Internal-Key)를 헤더에 넣어 보냅니다. 훨씬 단순하고, 사용자 계정 체계와도 섞이지 않습니다.

wrapper._auth = "bearer"는 뭔가. 함수에 붙인 메모입니다. tests/test_openapi.py가 모든 라우트를 훑으면서 “이 라우트는 인증이 필요하다고 코드에 표시돼 있는데, openapi.yaml에도 그렇게 적혀 있나?”를 대조합니다. 문서와 코드가 어긋나면 테스트가 실패합니다.

def haversine_km(lat1, lng1, lat2, lng2) -> float:
    rlat1, rlng1, rlat2, rlng2 = map(math.radians, (lat1, lng1, lat2, lng2))
    dlat, dlng = rlat2 - rlat1, rlng2 - rlng1
    a = (math.sin(dlat/2)**2 + math.cos(rlat1)*math.cos(rlat2)*math.sin(dlng/2)**2)
    return 2 * 6371.0088 * math.asin(math.sqrt(a))

왜 이렇게 했나

9.1 event_service.py — 화재 판정 (227줄)

판정 규칙: 고정 관측 창

“최초로 불꽃/연기를 본 순간부터 60초 안에, 검출 프레임이 30장 쌓이면 화재 확정.”

핵심은 창이 최초 감지 시각에 못 박혀 있고 절대 연장되지 않는다는 점입니다.

왜 창을 고정하나 — 이 파일에서 가장 중요한 설계

만약 창을 “마지막 검출 기준 60초”로 재면, 검출이 들어올 때마다 창이 뒤로 밀립니다. 그러면 59초마다 한 번씩 튀는 신호가 시간만 충분하면 결국 30장을 채워서 화재로 확정됩니다 — 그건 불이 아니라 노을·헤드라이트·반사광입니다. 이 로직이 걸러내려던 바로 그 신호죠.
창을 고정하면 “60초 안에 30장”이라는 밀도 조건이 되어, 지속적으로 강한 신호만 통과합니다.

시각 → 0s ─────────────────────── 60s ────────────────────── │ │ └ 최초 감지 (창 시작) └ 창 종료 event_first_detected_at ▸ 이 안에 30프레임 쌓임 → CONFIRMED (화재 확정, 알림 발송) ▸ 못 채운 채 창이 닫힘 → DISMISSED (기준미달, 조용히 종료) 그 다음 검출은 쿨다운 없이 새 이벤트로 처음부터

상태뜻누가 만드나

PostgreSQL의 now()는 “지금 이 순간”이 아니라 “이 트랜잭션이 시작된 시각”을 돌려줍니다. 한 트랜잭션 안에서 몇 번을 불러도 값이 똑같습니다. 그래서 두 행의 alert_sent_at과 alert_deadline_at이 마이크로초까지 동일합니다.

문법

대상을 고르는 SQL — 제외 조건이 핵심

왜 이게 필요한가

SQL이 대상 목록을 뽑은 순간과 실제 처리하는 순간 사이에는 시간 간격이 있습니다. 그 사이에 사용자가 앱에서 “오탐 취소”를 눌렀을 수 있습니다.

DB의 UPDATE는 원자적(atomic)이라 “확인하고 바꾸기”가 쪼개지지 않습니다. 파이썬에서 if 확인: 바꾸기로 썼다면 그 사이에 끼어들 틈이 생깁니다.

픽스처는 테스트가 필요로 하는 준비물을 만들어 주는 함수입니다. 테스트 함수의 매개변수 이름으로 요청합니다: def test_login(client): → pytest가 client 픽스처를 찾아 자동으로 넘겨줍니다. autouse=True면 요청하지 않아도 항상 실행됩니다.

monkeypatch는 “테스트 동안만 함수/변수를 바꿔치기”입니다. 테스트가 끝나면 자동으로 원상복구됩니다.

반복되는 3가지 설계 원칙

① 실패해도 본 작업은 계속한다

이미지 그리기 실패 → 원본으로 전송. 로그 기록 실패 → 신고 계속. ITS 실패 → 저장된 주소. SMS 실패 → 알림 행은 생성. 알림 실패 → 검출 API는 200. “곁들이는 것”이 “본체”를 막지 않게 한다는 원칙이 코드 전반에 일관되게 적용돼 있습니다.

② 중복 실행은 막되, 조용히 막는다 (멱등)

send_alerts는 기존 알림 번호 반환, start_report는 진행 중 신고 반환, DB 유니크 인덱스는 UniqueViolation으로 방어. 에러를 내지 않고 이미 있는 결과를 돌려주는 방식입니다.

③ 판단 근거를 남긴다

report_log는 전송 1회마다 요청·응답·소요시간·에러를 통째로 남깁니다. 사후에 “왜 종로소방서에서 중부소방서로 넘어갔나”를 추적할 수 있어야 한다는 요구를 코드가 직접 만족시킵니다.
