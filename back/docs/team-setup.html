1. 모두 공통 — 개발 환경 준비

백엔드를 직접 만지지 않더라도, 서버를 띄울 수 있어야 프론트·AI 작업을 검증할 수 있습니다. 전원 아래 5단계를 한 번씩 해두세요.

1) 저장소 클론

git clone https://github.com/KimDohwan24/Fire_Prevention_and_Detection.git
cd Fire_Prevention_and_Detection
git checkout dev-Wang

2) 파이썬 가상환경 + 의존성

cd back
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
💡 Mac · Linux 는 .venv/bin/pip 입니다. 아래 예시들의 .venv/Scripts/ 도 모두 .venv/bin/ 으로 바꿔 읽으세요.
파이썬은 3.11 이상을 권장합니다 (3.14 에서 동작 확인).

3) PostgreSQL 데이터베이스 만들기

pgAdmin 이나 psql 에서 데이터베이스를 먼저 만들고, 그 안에서 스키마 스크립트를 실행합니다.

-- 1. 데이터베이스 생성 (이름은 반드시 fireguard)
CREATE DATABASE fireguard;

-- 2. fireguard 데이터베이스에 접속한 뒤, db/schema.sql 파일 내용을 통째로 실행
⚠️ db/schema.sql 첫 줄이 DROP SCHEMA IF EXISTS fireguard CASCADE; 입니다. 기존 데이터가 전부 지워집니다. 이미 쓰던 DB 가 있다면 실행 전에 확인하세요.
💡 초기에 DB 이름을 firegaurd (오타) 로 만든 사람이 있습니다. 이름을 맞추려면:
ALTER DATABASE firegaurd RENAME TO fireguard; (접속을 모두 끊은 뒤 실행)

4) 환경변수 파일 만들기

.env.example 을 복사해서 .env 를 만들고 자기 값을 채웁니다.

cp .env.example .env
항목설명
DB_PASSWORD필수. 본인 PostgreSQL 비밀번호
DB_USER보통 postgres
JWT_SECRET아무 문자열. 개발용이면 값이 있기만 하면 됨
CCTV_API_KEY선택. 국가교통정보센터(its.go.kr) 인증키. CCTV 스트림 주소를 최신 값으로 갱신할 때만 씁니다. 비워 두면 외부 호출 없이 DB 에 저장된 주소를 그대로 쓰므로, 없어도 개발·테스트는 됩니다
INTERNAL_API_KEYAI ↔ 백엔드 통신 키. 비워두면 개발용 기본값 사용
⚠️ .env 는 깃에 올라가지 않습니다(.gitignore). 실제 키·비밀번호를 .env.example 에 적지 마세요. 템플릿은 항상 값이 빈 상태로 커밋합니다.

5) 서버 실행 확인

cd back
.venv/Scripts/python app.py

브라우저에서 http://localhost:5000/api/health 를 열어 {"status":"ok"} 가 보이면 성공입니다.

테스트도 한 번 돌려보면 환경이 제대로 잡혔는지 확실히 알 수 있습니다 (테스트 전용 DB fireguard_test 를 자동으로 만들며, 개발 DB 는 건드리지 않습니다):

cd back

3. 프론트엔드 담당

할 일

  • docs/api-spec.html 정독 — 특히 공통 규칙 섹션 (에러 형식 · 페이징 · 상태값)
  • 로그인 → JWT 저장 → 이후 모든 요청 헤더에 Authorization: Bearer <토큰>
  • 실시간 알림 방식 결정 후 백엔드에 알려주기 (아래 참고)
  • CCTV 영상 재생 붙이기 (HLS — 아래 참고)
  • 화면 기획 공유 → 대시보드 통계 API 가 필요한지 백엔드와 판단

서버 주소는 환경변수로

# .env
VITE_API_BASE_URL=http://localhost:5000

# 코드
fetch(`${import.meta.env.VITE_API_BASE_URL}/api/auth/login`, ...)

배포할 때 코드를 고치지 않고 주소만 바꿀 수 있습니다.

실시간 알림 — 백엔드 권장안은 폴링

새 화재 알림을 화면에 띄우는 방식입니다. 백엔드는 3~5초 폴링을 권장합니다.

방식평가
폴링 (권장) 기존 GET /api/alerts 재사용 → 추가 개발 0. 동시 사용자가 소수라 부하 문제 없고, 연결이 끊길 일이 없어 시연에서 가장 안전. 다만 유예가 30초라 폴링 주기는 그에 맞춰 짧게(3~5초) 잡아야 한다 — 주기가 길면 관리자가 알림을 보기도 전에 유예가 지나간다
WebSocket양방향이 필요 없는 구조라 오버스펙
SSE동기 Flask 와 궁합이 나쁨 (연결 하나가 워커 하나를 점유)

최종 결정은 프론트가 하고 백엔드에 알려주세요. 폴링으로 가면 백엔드 작업은 없습니다.

🗳️ 확정 대기 중인 항목 — 프론트 담당이 이 한 줄만 답해주면 닫힙니다.

“알림 수신을 GET /api/alerts 3~5초 폴링으로 갈까요?”

예 → 백엔드 추가 작업 없음. 명세서에 한 줄 적고 종료.
아니오(SSE·WebSocket) → 백엔드에 신규 기능이 필요하므로, 결정한 방식을 알려주면 작업 계획을 잡습니다.

폴링 구현은 이 정도면 됩니다 — 새 알림이 있으면 화면에 배지·브라우저 알림을 띄우면 됩니다.

// 5초마다 내 알림을 확인한다
setInterval(async () => {
  const res = await fetch(`${BASE}/api/alerts?alert_status=SENT`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  const { items } = await res.json();
  // items 중 처음 보는 alert_no 가 있으면 알림 표시
}, 5000);

CCTV 영상 재생 — HLS

cctv_stream_url 은 HLS(.m3u8) 주소입니다. 백엔드는 영상을 중계하지 않고 주소만 전달하므로, 프론트가 직접 연결해 재생합니다.

import Hls from 'hls.js';

const hls = new Hls();
hls.loadSource(cctv.cctv_stream_url);
hls.attachMedia(videoEl);
  • Safari · iOS 는 hls.js 없이 <video src="..."> 로 바로 재생됩니다.
  • 지연이 5~15초 있습니다. AI 는 원본 프레임을 실시간으로 보므로 알림이 영상보다 먼저 도착할 수 있습니다 — 버그가 아닙니다.
  • 스트림 주소에 만료되는 인증 토큰이 붙어 있어, 오래 켜두면 끊길 수 있습니다. 끊기면 CCTV 정보를 다시 조회해 새 주소로 재생하세요.
  • 백엔드가 이미 조회할 때마다 최신 주소로 갈아끼워 내려줍니다 (GET /api/cctvs · GET /api/cctvs/<cctv_no> 둘 다). 그래서 끊겼을 때의 대응은 CCTV 정보를 다시 조회해서 받은 cctv_stream_url 로 다시 붙이는 것뿐이고, 토큰 갱신 같은 특별한 처리는 프론트에서 할 게 없습니다. 외부 조회가 실패해도 응답은 항상 200 이라 에러 분기도 필요 없습니다.

검출 이미지 표시

이벤트 목록의 thumbnail_url, 상세의 media[].media_url 은 그대로 <img src> 에 넣으면 됩니다 (API 주소만 앞에 붙여서). 인증 헤더가 필요 없습니다.

검출 상자를 그리려면 media_detections 의 box 값을 쓰세요. [중심x, 중심y, 너비, 높이] 이며 0~1 비율이므로, 이미지 실제 크기를 곱해서 좌표로 바꿉니다.

4. AI 모델 담당

할 일

  • 아래 백엔드가 가정한 전송 형식이 맞는지 확인 → 다르면 백엔드에 알려주기
  • CCTV 스트림(HLS)에서 프레임을 읽어 검출 → 결과를 백엔드로 전송
  • 스트림이 끊기면 GET /api/internal/cctvs?cctv_status=ACTIVE 로 주소를 다시 받아 재연결하는 루프 구현 (아래 "카메라 목록 받아오기" 참고)
  • 검출 프레임 이미지를 media/ 아래에 저장 (백엔드가 그 경로를 서빙)

카메라 목록 받아오기 — 끊긴 스트림을 되살리는 곳

감시할 카메라와 지금 유효한 HLS 주소는 아래 API 로 받습니다. 검출 전송과 같은 X-Internal-Key 헤더를 씁니다 (JWT 아님).

GET http://localhost:5000/api/internal/cctvs?cctv_status=ACTIVE
X-Internal-Key: <INTERNAL_API_KEY 값>

{
  "items": [
    {
      "cctv_no": 1,
      "cctv_name": "정문 카메라",
      "cctv_lat": 37.5665, "cctv_lng": 126.9780,
      "cctv_stream_url": "http://cctvsec.ktict.co.kr/9999/EXAMPLE.stream/playlist.m3u8?wmsAuthSign=FAKE-TOKEN-FOR-DOCS",
      "cctv_status": "ACTIVE"
    }
  ]
}
  1. 기동할 때 한 번 호출해 감시 대상(cctv_no ↔ cctv_stream_url)을 잡습니다.
  2. 스트림 읽기가 실패하면 이 API 를 다시 호출하고, 해당 cctv_no 의 cctv_stream_url 을 꺼내 그 주소로 재연결합니다.
💡 여기 내려오는 주소는 백엔드가 조회 시점에 최신화한 값입니다 (저장해 둔 값이 아님). 다만 결과가 5분(CCTV_URL_TTL_SEC) 동안 캐시되므로 5분보다 자주 다시 불러도 같은 주소가 돌아옵니다 — 주기적으로 폴링할 이유가 없고, 끊겼을 때만 다시 부르면 충분합니다. 외부 조회가 실패해도 이 API 는 항상 200 이므로 별도 에러 분기는 필요 없습니다. 자세한 규칙은 docs/api-spec.html 의 "스트림 주소 최신화" 를 보세요.

백엔드가 가정한 전송 형식

프레임 하나당 한 번 호출합니다. 불이 났는지 아닌지 판정하는 것은 백엔드가 합니다 — AI 는 "이 프레임에서 무엇이 보였는지"만 보내면 됩니다.

POST http://localhost:5000/api/internal/detections
Content-Type: application/json
X-Internal-Key: <INTERNAL_API_KEY 값>

{
  "cctv_no": 1,
  "captured_at": "2026-08-10T14:30:00",
  "media_url": "/media/events/raw/f001.jpg",
  "detections": [
    { "cls": "flame", "conf": 0.91, "box": [0.238, 0.259, 0.047, 0.113] },
    { "cls": "person", "conf": 0.77, "box": [0.412, 0.688, 0.031, 0.142] }
  ]
}
항목설명
clsflame · smoke 는 화재로 집계. 그 외(person 등)는 저장만 하고 판정에는 쓰지 않음
conf신뢰도 0~1
boxYOLO xywhn 형식 (중심x, 중심y, 너비, 높이 — 0~1 비율)
불이 없는 프레임detections 를 빈 배열로 보내도 됩니다
💡 판정 규칙: 최초로 화재가 검출된 순간부터 EVENT_WINDOW_SEC(기본 60초) 관측 창이 열리고, 그 창 안에서 검출이 일정 프레임 수(EVENT_THRESHOLD_FRAMES, 기본 30) 만큼 쌓이면 화재 확정(CONFIRMED) 되고 자동으로 알림이 나갑니다. 창은 최초 감지 시각에 고정되어 이후 검출로 연장되지 않으며, 미달인 채로 창이 닫히면 기준미달(DISMISSED)로 정리되고 이후 검출은 새 이벤트로 다시 셉니다. 시연 때는 이 값들을 낮춰서 빨리 확정시킬 수 있습니다.
⚠️ 스트림이 조용히 죽는 것이 가장 위험합니다. HLS 주소의 토큰이 만료되면 에러도 알림도 없이 감시만 멈춥니다. 스트림 읽기가 실패하면 반드시 GET /api/internal/cctvs?cctv_status=ACTIVE 를 다시 호출해 새 cctv_stream_url 로 재연결하세요.

5. 시연 준비 (다 같이)

가상 119 서버 띄우기

실제로 119 에 신고할 수는 없으므로, 소방청 접수 서버를 흉내내는 서버를 함께 띄웁니다.

cd mock-119
../back/.venv/Scripts/python app.py     # 포트 6000

신고가 도착하면 이 콘솔에 한글 로그가 찍히므로, 시연 화면에 띄워두면 좋습니다.

승계 시연 만들기

"가까운 소방서가 응답하지 않아 다음 소방서로 넘어간다"를 보여주려면, 소방서 두 곳의 endpoint 를 다르게 설정합니다.

-- 1순위(가까운) 소방서는 실패하도록
UPDATE fireguard.agency SET agency_endpoint = 'http://localhost:6000/report?mode=fail'
 WHERE agency_no = 1;

-- 2순위 소방서는 정상 접수
UPDATE fireguard.agency SET agency_endpoint = 'http://localhost:6000/report?mode=ok'
 WHERE agency_no = 2;

mode 값: ok(접수) · fail(장애) · timeout(무응답) · reject(거절)

시간 단축

기본 설정으로는 알림 후 30초를 기다려야 자동 신고가 나갑니다. 더 짧게 돌리려면 .env 를 조정하세요.

ALERT_DEADLINE_SEC=10       # 알림 유예를 10초로
EVENT_THRESHOLD_FRAMES=5    # 5프레임만 쌓여도 화재 확정
ESCALATION_INTERVAL_SEC=5   # 무응답 감지 주기를 5초로

스윕 주기(ESCALATION_INTERVAL_SEC)만큼 신고가 늦어질 수 있으므로, 유예를 짧게 잡을수록 주기도 같이 줄여야 실제 유예가 의도한 값에 가까워집니다.

시연 순서 예시

  1. 백엔드 · mock-119 · 프론트를 모두 띄운다
  2. AI 가 화재 영상을 감지 → 프레임이 쌓여 화재 확정
  3. 사용자에게 PUSH + SMS 동시 발송 (프론트 화면에 알림 등장)
  4. 분기 A — 사용자가 "화재 확인" → 즉시 119 신고
  5. 분기 B — 사용자가 "오탐 취소" → 전체 중단, 신고 없음
  6. 분기 C — 아무것도 누르지 않음 → 유예 경과 후 자동 신고 → 1순위 소방서 무응답 → 2순위로 승계 → 접수 완료

6. 자주 막히는 곳

증상원인과 해결
서버 실행 시 DB 접속 오류 .env 의 DB_PASSWORD 가 비어 있거나 DB_NAME 이 실제 DB 이름과 다릅니다. PostgreSQL 서비스가 켜져 있는지도 확인하세요.
테스트가 DB 를 못 만든다 테스트는 postgres 유지보수 DB 에 접속해 fireguard_test 를 새로 만듭니다. DB_USER 에 DB 생성 권한이 필요합니다.
psycopg2 설치 실패 파이썬 3.14 는 psycopg2-binary 2.9.11 이상이어야 합니다. requirements.txt 에 이미 반영돼 있으니 그대로 설치하세요.
API 가 401 을 준다 토큰이 없거나 만료됐습니다. 다시 로그인해 새 토큰을 받으세요 (기본 만료 12시간, JWT_EXPIRES_HOURS).
내부 검출 API 가 401 X-Internal-Key 헤더 값이 백엔드의 INTERNAL_API_KEY 와 달라서입니다. JWT 가 아니라 이 헤더를 씁니다.
영상이 재생되지 않는다 주소가 rtsp:// 면 브라우저에서 재생 불가입니다(HLS 여야 함). HLS 인데도 안 되면 스트림 토큰 만료이거나 CORS 문제이니, CCTV 정보를 다시 조회해 보세요.
이미지가 404 파일이 media/ 아래 실제로 있어야 합니다. media_url 이 /media/events/12/f.jpg 면 파일은 media/events/12/f.jpg 에 있어야 합니다.
알림이 오지 않는다 점검 모드 이벤트(event_is_test=true)는 알림·신고가 나가지 않습니다. 또 CCTV 에 담당 사용자(user_no)가 지정돼 있어야 그 사람에게 갑니다.
신고가 두 번 나간다 나가지 않습니다. 진행 중인 신고는 이벤트당 1건만 허용되도록 DB 인덱스로 막혀 있습니다.
깃에 문서가 안 올라간다 의도된 규칙입니다. *.md 는 깃에서 제외되고, 팀 공유 문서는 .html · .sql 로 만듭니다.

막히면 백엔드 담당에게 문의하세요. API 요청·응답 형식은 docs/api-spec.html, DB 구조는 db/schema.sql 에 한글 주석과 함께 정리돼 있습니다.
